# `ui.faction_setup.v1`

Inputs describe ordinary random-map/Tiny/Citizen/standard-rules setup, followed
by explicit public control actions on the faction roster and leader editors.
They contain source-profile identifiers and actions, never expected answers.
Each original case resets the process and INI in a private pinned Wine profile.
The recorder requires two independent complete identical runs before writing a
reference. Pilot captures are private diagnostics and are not evidence.

Checkpoints observe the actual seven ordered roster rows, highlighted/previewed
row, separate selected/random play modes, editor captions, labels, focused value
and buttons, plus sliding-menu return paths. A roster edit expands into opening
the actual slot dropdown and clicking an option ordinal. Focus is an explicit
input: customization cases visit all seven fields rather than having the
observer click them implicitly. Input values preserve their actual case and
spaces. Captions, button labels and field labels use uppercase/whitespace
normalization; trailing field-label colons are excluded.

Roster text comes from the actual original control's linked items and string
objects. Seven distinct ordered nodes, mutual links, closure, type identities,
source-process ownership and mapped data bounds are checked. Play-mode flags
must be complementary. The focused input is read through the actual focus root
and edit-control type; no relative allocation layout, keyboard queue, source
file text or requested input supplies its answer. Only verified data addresses
and object offsets are used; no instructions or memory are patched. Rendered
title frames, labels and buttons are independently observed with OCR consensus.
Successful OCR results may be reused only for identical actual region pixels.

Four source profiles distinguish common Script.txt, expansion xscript.txt and
conflicting overrides. The combined profile also changes the faction title
label and seven Cybernetic UI fields. They are fixture inputs and are hashed
separately from observed outputs. Original paragraphs and artwork remain private.

This contract excludes quotation/portrait fidelity, Info/Datalinks content,
dropdown short-label typography, caret/selection geometry, name confirmation,
world generation, opponent population/AI, gameplay faction bonuses and complete
game parity. A candidate that launches before the name screen reports its actual
`starting` request boundary; it cannot fabricate a name dialog or generated world.
Full gameplay handoff remains a separate integration check. Missing controls,
malformed/incomplete traces, unsupported actions and failed workers are strict
failures and never count as passing comparisons.

The original 80-case recording and two additive random-customization cases are
separate immutable inputs/evidence pairs. The additive cases observe every field
when Change Name is clicked in random mode, with and without a preview. They
establish that customization returns to selected mode, and that no-preview
customization uses the last roster row. The first recording's six ambiguous
label glyphs are documented in [evidence-errata.md](evidence-errata.md); a fresh
complete isolated-label recording supersedes that observation method.

Candidate replay freezes one source snapshot and uses at most two concurrent
workers, with at most two fresh native settings fixtures per worker process.
Every batch binds its exact scripts and runtime hashes, and malformed, partial
or reordered traces fail. The native faction catalog's display boundary runs the
production faction configuration while omitting artwork/base-name loading.
Opponent setup and the world-start request remain controlled boundaries.

Separate browser regressions use actual native controls and SDL input. They check
rapid shifted typing, the 23-character name cap, selected and random setup, and
transfer of the entered name into the real backend Player. A normal Tiny world
then grows and produces a Colony Pod through real turns. These are application
integration checks, not original world-generation/name-confirmation evidence.
