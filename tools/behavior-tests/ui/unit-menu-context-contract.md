# Action-menu context after Tab navigation

`ui.unit_menu_context.v1` declares twelve fresh-game sequences with the same
healthy unspent stacked Scout, Former and Colony Pod and one-Doctor city as
`ui.unit_menu_orders.v1`. One or two initial real Tab presses precede MENU,
Action header four, source slot 26, 29 or 30 and a final Tab. Two source profiles
are unchanged from the earlier contract, including the edited title/three labels.
The generator supplies requested controls only; it supplies no selection, menu
rows, native orders, movement or closure answers.

Each full trace preserves the initial state and every action checkpoint: 78
checkpoints across twelve inputs. The original observer reuses the immutable
real-control/glyph/native-state capture from the earlier contract, while this
contract validates its own input sequences. It runs a fresh original process
and fixture for each case and requires two identical whole independent runs.
No outcome-dependent input retries, inferred menu rows or manual command effects
are permitted. Native city/unit identity, ownership, membership, health, stores,
positions, citizen state and year remain strict guards.

Candidate replay must execute the mounted production row callback selected by
its actual source identity and shared native Tab controls. Actual browser input
is a separate gate. Other initial orders, spent movement, active work, transport,
other commands or menus, general availability, turn advancement and full-game
parity remain outside these sequences. Input generation and schema validation
alone do not establish original evidence or candidate agreement.
