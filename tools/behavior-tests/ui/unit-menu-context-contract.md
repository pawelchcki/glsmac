# Action-menu context after Tab navigation

The HOT reference `unit-menu-context` contains twelve accepted
`ui.unit_menu_context.v1` inputs and 78 complete checkpoints. Every input was
recorded twice in independent actual original executions. Two disjoint six-case
records were combined without changing inputs or outputs; their canonical record
fingerprints, repeat counts, suite fingerprints and capture timestamps remain in
`reference.recording_partitions`.

The original input-only case file is unchanged. The full reference supersedes
[Former/Sentry](unit-menu-context-former-sentry-contract.md),
[Colony/Sentry](unit-menu-context-colony-sentry-contract.md) and
[Former/Hold](unit-menu-context-former-hold-contract.md). Those three case/gold
pairs remain byte-identical and receive static integrity checks through the
root [pilot archive catalog](../unit-menu-context-pilots-catalog.json). Their
outputs exactly match the corresponding full-record inputs and are counted
once. Promotion adds nine distinct cases: the active UI catalog now has
47 references/724 cases, including three HOT references/30 cases.

The declared healthy, unspent Scout, Former and Colony Pod share an owned
one-Doctor city with guarded resources. One or two initial actual Tab presses
select Former or Colony, then MENU, header four, source slot 26/29/30 and final
Tab are observed. The synthetic and action-edited source profiles supply wording
only; labels do not select native roles, callbacks or expected effects.

Every trace preserves the initial state and each action checkpoint: native
selection, orders, movement in thirds, menu/header/child presentation, ordered
source labels, text tones and separators. City/unit identities, ownership,
membership, health, stores, positions, citizen state and year remain guarded.
The Former Action child has twenty rows (sixteen light text controls and four
separators); Colony has twenty-two (seventeen controls and five separators).
Sentry and Hold preserve movement; Skip spends a movement point. The exact
recorded selection, child closure, retained root and final Tab are compared.

The pre-change full native baseline matched all twelve cases, with zero
mismatches, unsupported cases or errors. It used one display-free worker with
current production scripts and the unchanged cached runtime; no additional
production fix or memory batching was needed. Five distinct selected context
cases have actual browser pointer/SDL verification: the three original pilots,
plus edited Former Skip and edited Colony Hold. This does not claim a complete
twelve-case rendered replay.

Candidate replay executes mounted production callbacks selected by actual
source identity and shared native Tab controls. The browser observer records
successful native Show/Hide commands by node identity, omits hidden rows/targets,
requires current-coordinate native hover and exact clicked-source identity,
and compares two complete stable snapshots per checkpoint. It does not read an
independent visibility getter or prove arbitrary pixel/clipping equivalence.

The optional HOT/gameplay browser aggregates now select the full harness. The
three historical pinned pilot wrapper commands remain available separately.
Partial evidence, changed inputs and incomplete checkpoints remain failures.

Reference-only recording routes through `unit_menu_context_saved_original.py`
with `--child` to retain one sequential owner and fresh fixture loading per case.
The exact recorded source archive remains unchanged. The public launcher has its
own future recording fingerprint; no rerecording under that launcher is claimed.
`SMAC_UI_SAVED_FIXTURE_ROOT` and `SMAC_UI_WINDOWS_PYTHON_ROOT` are private recording
dependencies; public candidate replay needs neither original assets nor these
original-capture environments. Implementation did not inspect reference sources
or saved-fixture bytes.

Other initial orders, spent movement, active work, transport, commands, menus,
general availability, turn advancement and full-game parity remain outside this
contract. The pending signed nutrient-counter/base-recalculation discrepancy is
unchanged and excluded from passing totals.
