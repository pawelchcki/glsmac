# Terraform menu presentation across native unit contexts

`ui.terraform_menu_presentation.v1` compares the complete visible menu after
ordinary MENU/header clicks, Escape and native Tab navigation. Three public
synthetic source profiles retain the same command identities and prerequisites:
a nominal rate of four, edited Farm/Mine/Forest/Road names, and independently
varied declared work rates from one through four. Source fields are inputs;
row text, availability, grouping and time suffixes are observed outputs.

Preparation uses the same healthy unspent Former on flat arid nonbase land as
`ui.terraform_menu_work.v1`, including actual initial Tab navigation from the
ready Scout. Each seven-checkpoint trace opens the Former Terraform child,
presses Escape, navigates to the Colony Pod, opens MENU again and clicks the
Terraform header. The final checkpoint observes that actual click, including
whether a child exists and how its retained header highlight changes. This
trace alone does not establish Colony Terraform availability.
`initial_base` describes the city before spread preparation. Each engine's
post-preparation native city and companion state remain guarded independently.

Every checkpoint reports actual selected role, zero year delta and either no
menu or all nine visible header labels/highlights plus the visible child rows.
Rows report their rendered label and light/dark text class, or an actual
separator. Original observation reads complete captured glyphs and palette
classes. A separate read-only native-control audit independently confirmed the
recorded labels, including the original literal `(1 TURNS)` and `(2 TURN)`
suffixes; these are observed text, not grammatical corrections. Candidate observation reads the mounted production display nodes,
actual visibility and resolved text colors. It must not substitute source
entries, static descriptors or expected rows for the mounted menu.

The candidate also guards unchanged native unit identities/positions,
companion orders/movement, Former order/work/movement and all four relevant
terrain flags, city identity/population/stores/project, and zero emitted
command requests. The comparison uses real selection and menu handlers;
fixture display nodes, timers, initial layout and frontend notifications are
explicit boundaries. Default replay needs no original assets, rendering or
C++ relink. Rendered hit testing remains separately reported.

Accepted evidence requires fresh original fixtures for every case and
`compare.py record --repeat 2` with identical complete outputs and metadata.
A private original-created save may supply verified input state, never output
answers. Original assets, executables, saves and screenshots stay local.
The failed exploratory capture with rates through seven remains local: OCR
could not independently agree on a rate-five/six glyph. This accepted fixture
is explicitly bounded to rates one through four; no ambiguous output is
corrected from source values or counted as verified.

This scope excludes work execution and completion, costs outside the declared
rates, technology gating, other terrain/status/unit contexts, general Terraform
availability and AI. Command effects retain their separate work-menu contract.
