# First owned-city starvation notification

`ui.starvation_dialog.v1` compares the first starvation notification in a fresh
Gaian/Citizen/standard flat-arid game. The declared city starts with one Doctor,
zero nutrients and nine minerals. W/W selects its Colony Pod, B joins it, a
complete management opening reconciles its unassigned citizen, Escape closes
management, and H/H holds the two surviving companions before TURN COMPLETE.
The original's visible project is an incomplete Formers project. This contract
does not establish its price or mineral-processing algorithm.

Each case observes the actual notification caption, wrapped body, both choices,
highlighted choice, and both button labels. The body substitutes the actual
native city name; that independently read name is normalized to `{BASE}`.
Wording is uppercase and whitespace-normalized; OCR typographic apostrophes are
folded to ASCII. Three scales must agree. Distinct common/expansion/both source
profiles test which installed STARVE block contributes the wording, and separate
indexed label edits test the choices and suppression-button wording.

The trace also records native population, Worker/Doctor counts, worked tiles,
owned-city count, year and surviving companion orders/movement. Native identities,
ownership and positions are guarded. The original increments the year before
this notification is answered; a year change alone cannot prove city processing
has finished. Up/Down and Enter use actual original controls. Zoom continuation
requires a complete readable base HUD and matching native city title. Map
continuation requires absence of the known notification selection paint and
base title, plus the visible TURN COMPLETE control. Known research dialogs are
handled only after their own existing visible caption guards.

Raw signed nutrient counters remain in the separate unresolved opening contract.
This contract excludes mineral income, production ordering/prices, audio,
suppression-button activation, Escape on the notification, other citizen types,
factions, populations, terrain and general economy rules. Source edits are test
inputs, never OCR answers. Each reference case must come from independently
repeated original executions. Only successful candidate replay can promote it
from pending transfer into the passing catalog.

The display-free candidate executes shipped preparation, selection, joining,
management opening/closing, Hold controls, native turn advancement and queued
base growth. The mounted production popup receives the resulting notification;
the fixture never creates an expected notification itself. Source inputs go
through the native text parser and production consumer. Observations read the
actual popup labels/highlight and native citizens/units. Rendering, resource
geometry and synchronous frontend transport are explicit boundaries. The real
native Formers project has a synthetic non-completing price; its price, credited
minerals and general production ordering are not compared. Browser replay uses
the same frozen observations and verifies the actual controls and event bridge.
