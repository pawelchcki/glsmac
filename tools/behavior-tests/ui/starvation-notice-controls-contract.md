# First starvation notice: Escape and suppression controls

`ui.starvation_notice_controls.v1` compares four additional control sequences
on the first owned-city notification in the declared Gaian/Citizen/standard
flat-arid context. Preparation matches the separate starvation-dialog contract:
initial one Doctor, zero nutrients and nine minerals, actual W/W/B, complete
Enter/Escape management, H/H and TURN COMPLETE. The visible Formers project stays
incomplete; its price is outside this contract.

The new actions are normal Escape at the default highlight, Down then Escape,
Shift+Escape, and a click on the visible suppression button at the default
highlight. Every trace begins with the actual pending notification. Each action
observes the real screen, wording/highlight where present, native population and
jobs/worked tiles, relative year and surviving companion orders/movement. Native
city/unit identities, ownership and positions are guarded. Management requires
its complete resource HUD and actual title; map continuation requires absence of
the known notice/base title and a stable visible TURN COMPLETE control. A year
change alone is insufficient.

Each entire original capture must be independently repeated with fresh game
state. Source text comes from the installed default files, independently read by
OCR, with the existing uppercase/whitespace/apostrophe and base-name normalization.
New adapter/source fingerprints require fresh recording. Recorded answers are
immutable; display-free candidate replay must use actual native turn/growth and
mounted production popup controls. Display/timer/transport boundaries must be
declared and must never manufacture a notice, confirmation, population change,
or continuation. Real browser input checks the event bridge separately.

Both independent original runs agree on these outcomes:

| Sequence | Final screen | Native population | Notice selection |
| --- | --- | --- | --- |
| Escape | Complete base management | 1 | Confirm default Zoom |
| Down, Escape | Map with TURN COMPLETE | 1 | Confirm Proceed |
| Shift+Escape | Pending notification | 2 | Preserve default highlight |
| Suppression button | Map with TURN COMPLETE | 1 | Immediate Proceed continuation |

The frozen reproduction baseline has four strict mismatches, with no errors or
unsupported cases: ordinary Escape and suppression remain pending, while
Shift+Escape hides the notification with population still two. Recorded original
answers stay separate from these candidate results. The corrected native replay
and all four actual browser paths now match, with clean engine exits. Eleven
separate application regression scenarios cover authoritative confirmation, delayed
receipts, duplicate/stale input, rejection/retry, cleanup and rollback.

Suppression coverage is its immediate activation effect only. Future preference
persistence and later-notice suppression remain unobserved. Other modifiers,
Enter/OK behavior beyond the existing wording contract, raw nutrient meanings,
mineral income/prices/completion, artwork/audio, other factions/populations and
general economy remain outside this contract. Passing these four cases cannot
establish full notification or full-game parity.
