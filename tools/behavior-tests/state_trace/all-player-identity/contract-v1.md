# All-player duplicate-faction identity, version 1

The frozen `game.all_player_identity.v1` profile uses the previously observed
base-seven setup with Gaia in both rows0 and1, selected human row0, stock text,
Citizen, standard rules, flat-arid native40x80 map, and original seed1 immediately
before faction confirmation. Two independent input cases author `Deirdre` and
`Trace Commander` in the actual human Name editor; all other actions and fixture
controls are identical. Each case observes actual first-post-world Planetfall.
Neither case uses candidate state, expected opponent values, or identity writes.

The output retains every actual owner1..7, actual installed faction filename,
actual human flag, and the six previously independently verified native textual
identity fields: `leader_name`, `formal_name`, `noun`, `adjective`, `leader_title`,
and `leader_description`. Strings are bounded actual process readbacks at stable
Planetfall, not faction-source/template substitutions. No other-player identity
is omitted from repeatability checks. The complete array must reproduce across
two independent complete runs before acceptance.

The actual human's visible Name prompt caption, label, initial typed value and
buttons are observed; actual Planetfall caption and first rendered narrative
line provide a human-name cross-check. This does not provide rendered identity
coverage for offscreen opponents. No contact or diplomacy action is performed.

`gender` is explicitly null/unsupported for each owner: this profile does not yet
have a verified native per-owner gender read. The human Name editor's actual
rendered gendered label is a separate UI observation, not a substitute for all
seven gender values. A distinct `player_display_name` is also null/unsupported:
this profile verifies the leader-name string, not an independently identified
scoreboard/network-player name field. Raw pointers and unverified bytes are not
semantic identity fields.

Comparing the two complete authored-name cases can establish which observed
player fields differ under this bounded name input. It does not claim broader
custom-faction cloning, save/load, diplomacy rendering, or unrelated template
mutation behavior. Unsupported fields remain explicit; no full identity or full
presentation parity claim is made. This evidence remains outside the passing
catalog/default totals until a versioned public adapter replay is integrated.
Old accepted setup-controls and state-trace files/manifests remain untouched.
