# Base Operations navigation projection v1

`base_operations.py compare --runtime PATH --report PATH` replays the shipped
MENU → HQ source slot 7 binding, mounted report, row selection, two-click city
opening, Escape back to the selected report and Escape back to the map. It uses
actual native seven-owner startup, city data, event validation/application and
the shared city-management reconciliation/opening path. Display transport is
controlled in the asset-free GSE replay. The separate Playwright check delivers
actual pointer clicks and Escape keys to the production UI.

The immutable accepted files in `ui/reference-drafts/` record two agreeing
original runs. `base-operations-source-bindings-v1.json` binds the complete source case, raw observations, visual
observations, readable contract and independently derived UI semantics. The
public projection compares five UI checkpoints, including the live faction
adjective/report title, three tabs, Production selection, city/project names,
selection and visible buttons. City-panel name/project typography is explicitly
unsupported: the report retains the original uppercase strings and raw candidate
strings separately, with no case conversion or tolerance. The opened native
city identity and source recipe/name binding are asserted within the candidate.
Original native arrays are independently checked
for all seven owners at all eight report-control fences.

The candidate receives declared source inputs and a controlled native world,
never original post-action state. The fixture supplies an equivalent first-city
name before native factories run. Report content comes from current native
cities, ownership and recipes, and source labels; it does not supply a fixed
city or project in product code. Edited-source, renamed-city, changed-project
and multiple-city regressions guard those bindings. Source HQ slot 7 is an
observed menu binding. The application's labels.txt slot mapping is explicit;
original report-label precedence is unobserved.

Within each candidate replay, deep primitive snapshots before/after every
control fence compare all owners, roles, faction identities, technologies,
research, unit identities/owners/positions/prototypes/movement/orders/health/
morale, base identities/owners/positions/names/population/production/minerals/
nutrients/intake/consumption, citizen identities/types/worked tiles and facility
names. Missing or duplicate owners/entities and incomplete UI/fence output fail
closed. No live wrapper is used as the baseline. The transport reports the
validated inventories and immutable runtime/script hashes; native execution is
recorded separately from source/reference validation. Hidden engine fields not
exposed through these APIs remain unobserved.

Full original world/unit-prelude equality, numerical price/progress/turns,
signed food and mineral policy, exact report pixels/artwork, project icons,
audio, animation timing, original double-click cadence, other tabs, F4 and
keyboard row navigation, Datalinks/governor effects and multi-city ordering
remain unsupported. The 400 ms two-click window and persistent-ID row ordering
are application policies. CLOSE has a local lifecycle regression; the original
record exercises Escape. These limitations remain outside passing totals:
`full_trace_status` is `unsupported` and `full_trace_passing_cases` is zero even
when the bounded UI projection matches.

The report owns and cancels its click timer and fences callbacks by generation,
owner, turn, live native base identity and UI lifetime. Opening a row reuses the
native management acknowledgment path. Rejection can return to the report and
retry; stale receipts cannot replace another modal or a newer report session.

Validation for this implementation used baseline `1e8913f6a59819975ebc8ef54a6108d9bf59b7d2`:
all 190 production scripts in the retained old-source snapshot matched that
commit byte for byte. Actual native MENU/HQ slot 7 was inert before the change.
The combined candidate engine was pinned to JavaScript SHA256
`3679f92f438128382f7cb3c235306a79bcd4f5f9f3e8286698d699e22bbc782c`
and WASM SHA256
`79ddb4d63a107ac1b112e8fb71ba61963d37979edb244b4816eb2beab32e093d`.
Ten Python integrity/failure-accounting tests pass. The two new native suites
and adjacent object-list lifecycle, citizen reconciliation and rename suites
pass 52 scenarios/226 assertions. The final installed-asset browser check passes
the pointer/keyboard roundtrip, native preservation, effective footer bounds,
nonoverlapping reachable buttons and actual pointer Close. Its production-script
snapshot SHA256 is
`54454e8544739db10f5f8f0a6b8a865ddb9ac7ee7d4659a52d65111375a71bc1`.

Actual browser execution exposed and corrected native String/Objectref label
construction and a footer alignment overlap that display mocks did not detect.
Preliminary observer/teardown errors and the eight-fixture aggregate WASM heap
limit were retained as nonpassing evidence; the eight scenarios now run in two
isolated processes. These checks do not cover player-wide balances/diplomacy/
visibility, unit internal work-progress flags, facility internals or arbitrary
script-owned fields beyond the enumerated detached snapshots. Such fields,
media transitions and broader world equality remain observation gaps.

The delayed-acknowledgment regression also reopens MENU → HQ slot 7 while an
older city preparation is pending, then double-clicks the same city. A new report
session sends a fresh request token and selection epoch; the older response
cannot consume its continuation. Its own successful native response opens the
city and Escape returns to the selected report, preserving all captured owners.
Only ordinary-to-ordinary base-selection repeats share a pending request.
Transitions into or out of a report continuation use the current intent with a
fresh token, including actual base-icon selection after a reopened report
closes. An ordinary city close returns to the map without resurrecting a report. Native preparation remains authoritative and idempotent when no idle
citizen needs reconciliation; a repeated no-op returns receipt zero.
